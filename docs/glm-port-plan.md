# GLM-5.3-Flash NVFP4 у Strata: план і оптимізації

Мета: перший запуск GLM-5.3-Flash NVFP4 (204 GB) на RTX 5090 32 GB + 128 GB RAM + 2 NVMe
(C: 9100 PRO PCIe 5, ~13.4 GiB/s unbuffered; D: 990 PRO PCIe 4, ~7 GB/s).
Старт: llama.cpp, UD-IQ4_XS, 2 SSD — prefill 29 tok/s, decode 2.4–2.9 tok/s (8K prompt).

Рішення: **повний нативний порт у рушій Strata** (варіант A). llama.cpp master (`D:\Projects\llama.cpp-glm`,
`src/models/glm5-next.cpp`) — лише еталон правильності (логіти для KL, дампи тензорів), не рантайм.

## Бюджет пам'яті

- **VRAM 32 GB**: 1.5 резерв (#279) + 8.8 щільні Q8_0 + ~1.3 кеші (64K) + 0.15 KDA + ~1.5 робочі буфери
  → **~18.6 GB під експертів ≈ 1,310 (10.8%)**.
- **RAM 128 GB**: 6 Windows + ~3 рушій → **~118 GB ≈ 8,300 експертів (68.6%)**, pinned, large pages,
  без дублювання тих, що у VRAM (наш tier).
- **SSD**: решта **~2,490 експертів (20.6%) ≈ 35 GB**, рознесені на обидва диски.

## Модель швидкості decode (на порядок величини)

Межа — пропускна здатність DRAM: CPU pool у логах Strata мав 53–57 GB/s; DMA для PCIe-частки теж читає DRAM.
Промах з RAM коштує ~14.2 MB з DRAM, промах з SSD — ~14.2 MB з диска (C+D разом ~20 GB/s, з prefetch).

| сценарій (частки викликів VRAM / RAM / SSD) | промахи з RAM за токен | SSD за токен | decode без драфтів |
| --- | ---: | ---: | ---: |
| гарячий хвіст як у Qwen (50 / 47 / 3%) | 2.2 GB, ~30 мс з PCIe-часткою | 0.14 GB, 7 мс (паралельно) | **~30–35 tok/s** |
| розмазаніший (35 / 57 / 8%) | 2.7 GB, ~36 мс | 0.38 GB, 19 мс | **~25 tok/s** |

Проти 2.4–2.9 у llama.cpp: **~10×**. Точну цифру дасть профіль маршрутизації (етап M0).

Prefill (чанк 32K): усі 171 GB експертів проходять один раз на чанк — ~2.4 с з RAM по PCIe + ~1.8 с з SSD
(частково паралельно) + обчислення ~4 с (W4A8 MMQ, ~18B активних) → **~4–6K tok/s** (llama.cpp: 29).

## Оптимізації, за пріоритетом

1. **Розміщення експертів за профілем на 4 рівнях** (VRAM / pinned RAM / SSD C / SSD D). Профіль —
   `llama-moe-profile` (рахує виклики й вагу кожної пари шар-експерт) → `expert-profile.bin`. Найхолодніші
   ~20% йдуть на SSD, найгарячіші на швидший C:.
2. **Адаптивний VRAM-tier** (є у Strata): гарячий набір стежить за розмовою, заміни раз на 4 раунди.
   Для 14 MB експертів 96 замін = 1.4 GB по PCIe за 4 раунди — прийнятно.
3. **Максимум VRAM під експертів**: щільні в Q8_0 (не BF16, як у чекпоінті: −7.7 GB = +540 експертів);
   MLA latent та indexer-кеш у FP8/INT8; shared experts у NVFP4 (+0.5 GB); lm_head Q8_0.
4. **Передбачення експертів наступного шару**: router шару l+1 — лінійний від нормованого стану, тож із
   виходу шару l (через hc_pre) можна наперед порахувати top-k і почати prefetch з SSD/RAM → PCIe раніше.
   Ховає латентність SSD і PCIe-копій. Точність передбачення — виміряти.
5. **Драфтер (MTP, шар 45) лише на резидентних у VRAM експертах**: маршрутизація драфту маскує експертів,
   яких нема у VRAM (з перенормуванням). Драфт тоді не робить жодного промаху; точні токени все одно дає
   verify. Власні експерти MTP (BF16 у чекпоінті, 14.5 GB) — у NVFP4 або IQ4 і теж у tier.
6. **Спекулятивний decode з урахуванням перекриття**: на MoE 8/288 вікно з W токенів тягне об'єднання
   експертів. Якщо сусідні токени мало перекриваються, довгі вікна не зменшують трафік експертів. Довжину
   вікна підбирати за виміряним перекриттям (`llama-moe-profile` рахує distinct на вікно W = 1..8).
7. **Розподіл промахів CPU / PCIe з урахуванням DRAM**: обидва шляхи читають ту саму DRAM. Частку
   підібрати заново для 14 MB експертів, як для NVFP4-Qwen (0.25 проти 0.55).
8. **Злиті ядра + один CUDA graph на вікно**: mHC pre (RMS + 24 мікси + Sinkhorn 4×4 ×20) і post
   одним ядром кожен (як fused_gr для HC у Qwen); крок KDA одним ядром (conv + gates + l2 + delta-rule +
   RMS·sigmoid); MLA decode з поглиненими `wk_b/wv_b` + вибір із indexer одним проходом.
9. **Prefill**: чанки 32–64K (#282); KDA спершу через рекурентність по токенах (як gdn_rec_cols), потім
   chunked-алгоритм на tensor cores; indexer: скоринг пулів як GEMM + швидкий top-k (є у QSA select);
   експерти через W4A8 MMQ (є).
10. **Опційний «швидкий режим»**: пропускати промах з SSD, якщо його вага маршрутизації мала (< ~3%),
    з перенормуванням решти. Лише opt-in, з виміряним KL.

## Архітектура порту (з розвідки коду Strata, коміт 57a7b1f)

Per-layer код Strata повністю під Qwen: форма моделі зашита в `layout.hpp:27–59` (ModelGeometry),
`prefill.cpp:66–68` (N=2560, K=10, NE=512 — `init` відмовляє інакше), `mtp.cpp`, `cpu/expert.hpp:34–51`
(H=2560, FF=640, NE=512); router — softmax top-10 без bias (`router_top10`, `native_router_top10` лише для
512/10); shared expert з sigmoid-gate; немає щільних MLP-шарів; немає MLA, KDA, Sinkhorn, sigmoid+bias
routing, routed scaling; serve — лише шаблон, токенізатор і tool-call формат Qwen.

Тому: **окремий виконуваний файл `strata-glm`** (свої шари, verify, prefill, MTP, session) поверх спільної
бібліотеки експертів. Qwen-рушій (`generate.cpp`) не чіпаємо.

Спільне й уже параметризоване: `ExpertCache`, `ExpertSource`/`ArenaExpertSource`/`TieredExpertSource`
(ключ — шар, експерт), `load_experts_gguf`, `native_expert_grouped[_f32]` (`L.n_embd`/`L.n_ff`),
`mmq::Product/Context`, `router_top10` (довільні n_expert, k ≤ 64).

Треба параметризувати під GLM (H=4096, FF=2048, NE=288, 42 MoE-шари з 45):
- `cpu/expert.hpp` + `expert_layout.cpp:114` (native_fmt з H/FF) і `:137–143` (експерти в кожному шарі
  поспіль — у GLM шари 0–2 щільні);
- `expert_source.cpp:664–666, 683, 905–917` (перевірка `n_embd != H`, крок рядків, `kNativeActBytes` 4096);
- `pool.cpp:352–505` (розбиття CPU-завдань за FF/H);
- `ExpertDispatch::n_expert = NE` (`expert_source.hpp:159`);
- пакувальник `iq_pack.py` (N_EXPERT=512 на :112).

Нове для GLM: mHC (Sinkhorn), KDA (decode, verify-вікно, prefill), MLA NoPE + indexer з k-pool, router
sigmoid+bias+×2.5, щільний MLP, SwiGLU clamp, MTP-шар GLM, токенізатор/шаблон/tool calls GLM у serve.

  лімітом low-priority, окремий запуск резидентних експертів, метадані груп із pinned-пам'яті.
  Профіль chat_code: PCIe зайнята ~80% (≈3.2 GB/токен разом зі спекулятивними копіями) — межа без втрат близько.
- Опції з втратою: `--skip-ram W` (0.05: +3…6%, KL 0.018→0.020; 0.08: +20%, KL 0.044), `--skip-disk W`,
  `--dense-fp4 all` (+3…7%, KL 0.041 на довгому контексті).
- **3-бітні експерти відкинуто**: симулятор обіцяв −36% байтів PCIe і майже без диска (+40…55%), але fake-quant
  (`GLM_FAKE3`, знак + {0..3} × UE4M3 на 16) дав KL 0.19 і top-1 79% на довгому контексті.
- Відкинуто (виміряно): `--ram-exclusive` (158 write-back на токен, DDR5), `--pf-stage`, CPU share (повільніше),
  lossless стиснення експертів (ентропія кодів 3.97 біт з 4, lzma 97.6%); CPU share і зараз у межах шуму.
- Межа без втрат: PCIe ~50.8 GB/s (RAM→VRAM ~1.2–1.7 GB на токен) + диски (C: 13.4 GiB/s, D: 7 GB/s).
  100 tok/s фізично недосяжні на цій машині; `--skip-disk W` (з втратою) дає +30% при KL 0.022.
